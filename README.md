# Policy Data API with Blue/Green Deployment & Chaos Testing

**LOCAL SIMULATION.** No AWS was used. There is no live ECS, CodeDeploy, CloudWatch, or Fault Injection Service in this repo. Everything below was measured on a local machine; production equivalents are documented as design/IaC only.

FastAPI REST API over a synthetic policy/claims store. The local store is **SQLite, explicitly a stand-in for PostgreSQL** (`data/policy.db`, generated by `scripts/gen_data.py`: 2,000 policies, 5,000 claims, deterministic seed). Endpoints: `GET /health`, `GET /version`, `GET /meta/stats`, `GET /policies`, `GET /policies/{id}`, `GET /policies/{id}/claims`, `GET /claims`, `GET /claims/{id}`.

## Measured results (actual local run outputs)

| Experiment | Result |
|---|---|
| Load test (`scripts/loadtest.py`, 300 requests, TTL cache) | 300/300 success (100%), median 2.44 ms, **p95 6.28 ms**, mean 3.38 ms |
| Chaos, raw client (30% injected 503s + 50 ms latency, `CHAOS_FAIL_RATE=0.3`) | 142/200 success (**71.0%**), median 53.64 ms, p95 59.61 ms |
| Chaos, resilient client (retries + circuit breaker + health checks) | 195/200 success (**97.5%**), median 54.49 ms, p95 220.40 ms, 283 attempts |
| A/B cache test (200 req/arm, 50/50 split) | no-cache median 2.773 ms vs LRU median 2.374 ms → **14.39% median reduction**, Welch t on log-latency = 5.08, significant at the 95% criterion (\|t\| > 1.96) |
| Blue/green simulation (`scripts/bluegreen.py`) | Healthy green: promoted through 90/10 → 50/50 → 0/100 canary. Faulty green (42% error rate): **automatic rollback to blue** at the first canary step |
| Tests | **23 passed, 99% coverage** (`pytest --cov=app`: app/main.py 98%, all other modules 100%) |

Raw outputs are saved in `results_load.txt`, `results_chaos.txt`, `results_ab.txt`, `results_bluegreen_promote.txt`, `results_bluegreen_rollback.txt`. Reproduce with the venv interpreter, start servers with `uvicorn app.main:app --port <port>` (set `APP_VERSION`, `CACHE_STRATEGY`, `CHAOS_FAIL_RATE`, `CHAOS_LATENCY_MS` as needed), then run the scripts. Note: local scripts pass `trust_env=False` to httpx because sandbox proxy env vars otherwise break localhost URLs.

## Components

- `app/` — FastAPI app, SQLite store, three cache strategies (none / TTL / LRU), circuit breaker + retry helpers.
- `scripts/` — data generation, load test, chaos harness with resilient client, A/B experiment, blue/green canary/rollback simulation.
- `Dockerfile` + `docker-compose.yml` (blue + green services). **Docker was not available on the build machine (`docker: command not found`), so the image was never built or run — the Dockerfile exists and is complete, validated by inspection only.**
- `infra/terraform/main.tf` — documentation-grade IaC (never applied) sketching the production equivalent: RDS PostgreSQL, ECS Fargate + CodeDeploy blue/green with ALB target groups, CloudWatch alarm gates with automatic rollback, FIS experiment templates.
- `.github/workflows/ci.yml` — CI (pytest + coverage) plus a deploy job that documents the production blue/green process; it does not deploy anything from this repo.

## Production-design mapping (resume context, not reproduced here)

The originating role design ran this API containerized on ECS Fargate backed by PostgreSQL, released via CodeDeploy blue/green with Terraform + GitHub Actions and CloudWatch-alarm rollback, chaos-tested with AWS FIS. Those AWS systems, the 15+ production releases, and production latency/success figures **cannot be reproduced in a local sandbox and are not claimed by this repo** — only the local measurements in the table above are.

## Honest deltas vs. the production figures

- Local p95 (6.28 ms) is far under the production "<120 ms p95" figure, but the two are not comparable: local SQLite on loopback vs. ECS Fargate + PostgreSQL over a network.
- Chaos success with resilience measured **97.5%**, not 99.9% — retries raised it from 71.0% but did not reach the production figure.
- The A/B cache win measured **14.39%** median-latency reduction, not 38% (still statistically significant at 95% locally).
- Test coverage measured **99%**, above the 90% figure.
